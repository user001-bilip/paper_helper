## 1. 产品概述

Paper Helper 是一个面向科研人员的论文写作网站。用户选择平台已适配的期刊模板，或导入期刊提供的 LaTeX 模板后，在接近 Word、飞书文档的可视化编辑器中完成论文内容。系统负责维护论文结构、模板约束和排版映射，并导出可继续编译或投稿的 LaTeX 工程、PDF 和 Word 文档。

产品的核心不是提供另一款通用文档编辑器，而是把“论文内容”和“期刊排版模板”分离：用户专注写作，系统负责把结构化内容稳定映射到目标期刊格式。

## 2. 背景与问题

科研论文通常需要同时处理内容写作、章节结构、公式、图表、引用和期刊格式。现有工作流存在以下问题：

- Word 写作直观，但转为 LaTeX 或切换投稿模板时需要重复排版。
- LaTeX 排版稳定，但对不熟悉语法的用户门槛较高，写作反馈不够直接。
- 不同期刊的模板结构、宏命令和资源组织方式不同，换刊投稿时成本较高。
- 图片、表格、公式、参考文献分散管理，容易出现编号、引用或资源路径错误。
- 论文完成后才集中处理格式，容易在投稿前产生大量机械修改。

## 3. 产品目标

### 3.1 核心目标

1. 让用户像编辑普通文档一样创建论文结构和撰写内容。
2. 在写作阶段持续遵循所选期刊模板的结构约束。
3. 将标题、正文、图片、表格、公式等内容稳定映射到 LaTeX。
4. 导出结构完整、可检查、可继续编辑的论文文件，减少最终手动排版。
5. 保持项目、模板和科研资料的私密性与可迁移性。

### 3.2 MVP 成功标准

- 新用户无需编写 LaTeX 语法即可完成一篇包含标题层级、正文、图片、表格和公式的论文草稿。
- 用户能通过大纲面板快速创建、删除、移动和折叠论文结构。
- 内置模板导出的 `.tex` 文件能够通过对应 LaTeX 环境编译。
- 折叠、选择等界面状态不影响导出内容。
- 用户能导出 LaTeX、PDF 和 Word 兼容文件。

### 3.3 暂不作为 MVP 目标

- 支持所有第三方 LaTeX 模板的完全自动适配。
- 多人实时协作、批注和复杂权限管理。
- 自动生成整篇论文或代替用户完成学术判断。
- 完整替代 Overleaf、Microsoft Word 或专业 LaTeX IDE。
- 首版即提供完整的期刊投稿接口。

## 4. 目标用户

### 4.1 主要用户

- 需要发表期刊或会议论文的硕士生、博士生和科研人员。
- 熟悉 Word，但不熟悉或不愿频繁处理 LaTeX 排版的用户。
- 能使用 LaTeX，但希望减少模板修改、格式迁移和资源管理工作的用户。

### 4.2 次要用户

- 需要统一团队论文格式的课题组负责人。
- 负责论文修改、格式检查或投稿准备的合作者。
- 维护期刊模板适配规则的管理员或开发者。

## 5. 核心使用场景

### 场景 A：使用平台内置模板写新论文

1. 用户新建论文项目。
2. 选择中文期刊通用、IEEE、Elsevier 等已适配模板。
3. 填写论文标题、作者、摘要、关键词等基本信息。
4. 在大纲中创建章节，在编辑区完成正文、图表和公式。
5. 系统根据模板实时维护结构和排版规则。
6. 用户检查编译结果并导出 LaTeX 工程、PDF 或 Word。

### 场景 B：使用期刊提供的 LaTeX 模板

1. 用户上传期刊模板压缩包或选择已经适配的模板版本。
2. 系统识别主文件、文档类、依赖包、参考文献和资源目录。
3. 系统展示识别结果、缺失依赖和可编辑字段。
4. 用户确认模板映射后进入写作。
5. 系统将结构化内容写入模板指定位置并执行编译检查。
6. 编译通过后，用户导出完整投稿包。

若模板无法自动识别，系统必须明确提示“不支持的结构或宏命令”，并允许后续通过模板适配配置处理，不能错误地标记为可投稿。

### 场景 C：更换投稿期刊

1. 用户复制现有论文项目或创建版本分支。
2. 选择另一个已适配模板。
3. 系统保留论文内容和结构，重新应用目标模板规则。
4. 用户处理新模板要求的元数据和结构差异。
5. 系统重新编译并导出新的投稿包。

## 6. 产品原则

- 内容与模板分离：编辑器存储语义结构，不把页面视觉样式直接当作论文数据。
- 所见可写，导出可信：编辑界面追求直观，最终格式以模板编译结果为准。
- 结构优先：标题层级、图表、公式、引用均使用结构化节点保存。
- 渐进复杂：普通用户默认使用可视化编辑；高级用户后续可查看 LaTeX 源码和编译日志。
- 明确边界：不能成功解析或编译的模板必须给出诊断，不承诺“自动适配成功”。
- 私密与可迁移：项目文件、模板和项目技能包可随 Git 仓库迁移，不在仓库中存储密钥。

## 9. 关键交互规则

### 9.1 大纲加号

- 每个标题行提供加号按钮。
- 点击加号后显示紧凑菜单：同级标题、下一级标题、正文。
- 同级标题插入在当前章节结束之后。
- 下一级标题属于当前章节，并继承模板允许的下一层级。
- 正文紧跟当前标题插入，便于立即开始写作。
- 达到最深层级时禁用下一级标题，并给出原因提示。

### 9.2 删除标题

- 大纲提供直接删除入口。
- MVP 默认仅删除标题节点并保留正文，按钮提示必须明确该行为。
- 删除整个章节属于后续独立操作，必须有确认或可撤销机制。

### 9.3 展开与收起

- 标题收起后，标题本身仍显示。
- 隐藏范围从该标题之后开始，到下一个同级或更高级标题之前结束。
- 正文、图片、表格和公式的收起仅影响自身展示。
- 收起状态属于用户界面状态，不进入论文正文，也不影响任何导出格式。

### 9.4 模板与编辑样式

- 编辑区提供接近期刊排版的视觉提示，但不要求像素级复刻最终 PDF。
- 模板决定允许的标题层级、元数据字段、编号规则和导出结构。
- 用户修改内容时，不应直接修改 `.cls` 或 `.sty` 文件。

## 10. 数据模型概念

### 10.1 PaperProject

- 项目 ID、名称、所有者
- 当前模板及模板版本
- 论文元数据
- 文档内容
- 保存状态和版本信息
- 创建时间、更新时间

### 10.2 DocumentBlock

- 块 ID
- 块类型：标题、正文、图片、表格、公式等
- 标题层级
- 结构化内容
- caption、label、引用等属性
- 排序位置和父子关系

### 10.3 TemplatePackage

- 模板 ID、名称、版本和来源
- 主 `.tex` 文件
- `.cls`、`.sty` 和其他资源
- 模板映射配置
- 编译引擎和依赖
- 支持状态与诊断结果

### 10.4 ExportJob

- 导出格式
- 使用的项目版本和模板版本
- 任务状态
- 编译日志、警告和错误
- 输出文件信息

界面的选择状态、面板开关和折叠状态不应与论文语义内容混为一体。

## 11. 非功能需求

### 11.1 性能

- 普通论文项目打开后应在 2 秒内进入可编辑状态，具体指标在真实部署环境中校准。
- 常规输入操作应保持即时反馈，不因后台自动保存阻塞输入。
- 图片和长论文应采用增量保存与按需加载策略。

### 11.2 可靠性

- 自动保存失败时必须明确提示，并保留本地未同步内容。
- 导出任务使用确定的项目快照，编辑过程中内容变化不应污染正在进行的导出。
- 模板编译失败时保留源文件和日志，允许用户修复后重试。

### 11.3 安全与隐私

- 论文、实验图片、模板和参考文献默认视为私密数据。
- 不在前端代码、Git 仓库或技能包中存储密钥与令牌。
- 外部 AI 或科研服务集成必须明确告知发送的数据范围，并由用户主动启用。
- 上传模板包需要限制文件类型、大小和解压路径，防止路径穿越和恶意执行。
- LaTeX 编译必须在受限环境中运行，禁止任意 shell escape。

### 11.4 可迁移性

- 产品要求、架构约定和智能体协作规则随仓库保存。
- 项目本地技能包保存在 `.codex/skills/paper-helper/`。
- 不将核心编辑和模板能力绑定到某个外部插件或单一智能体服务。
- 导出的论文项目应可脱离本网站继续使用标准 LaTeX 工具编辑和编译。

### 11.5 可访问性

- 主要操作支持键盘访问和清晰的焦点状态。
- 图标按钮提供可读名称和提示。
- 颜色不作为错误、选择或状态的唯一表达方式。

## 12. 产品指标

MVP 上线后重点观察：

- 首次创建项目到写入第一段正文的完成率。
- 创建标题、正文、图片、表格和公式的成功率。
- 自动保存成功率及内容恢复成功率。
- 内置模板首次编译成功率。
- 导出任务成功率和平均耗时。
- 用户完成一篇草稿后进行手动排版调整的时间。
- 模板导入诊断中可自动识别、需人工适配和失败的占比。

## 14. 风险与应对

| 风险                              | 影响                   | 应对方向                                                       |
| --------------------------------- | ---------------------- | -------------------------------------------------------------- |
| 任意 LaTeX 模板差异过大           | 自动映射不可靠         | 首先支持已适配模板；对未知模板提供诊断和人工映射               |
| 可视化编辑与 LaTeX 表达能力不一致 | 导出结果与预期不同     | 使用结构化中间模型，明确可视化能力边界，并提供编译预览         |
| 浏览器富文本产生不稳定 HTML       | 内容和导出难以维护     | 使用 TipTap 等有 schema 的编辑器，不以原始 HTML 作为唯一数据源 |
| LaTeX 编译存在安全风险            | 服务器可能执行恶意内容 | 沙箱编译、禁用 shell escape、限制资源和超时                    |
| Word 与 LaTeX 格式无法完全一致    | 用户对导出效果误解     | 标注 Word 为兼容导出，投稿级排版以目标模板 PDF 为准            |
| 长论文和大量图片导致性能下降      | 编辑卡顿、保存失败     | 文档分块、增量保存、资源异步上传和后台导出                     |
| AI 或外部插件接触私密论文         | 数据泄露风险           | 默认不发送数据，逐项授权并展示数据范围                         |

## 15. 待确认问题

以下问题不阻塞当前 PRD，但会影响后续优先级：

1. 首个“可投稿级”模板优先选择中文期刊、IEEE 会议还是 Elsevier 期刊？
2. 第一版数据保存采用纯本地模式，还是直接加入账号和云端项目？
3. 自定义模板导入是面向普通用户自动完成，还是先由管理员/开发者建立适配器？
4. Word 导出是仅用于交流审阅，还是需要成为与 LaTeX 同等重要的投稿格式？
5. 第一版是否必须包含 BibTeX 和正文引用，还是先验证写作与模板导出？
6. 是否需要离线部署或课题组私有部署能力？
